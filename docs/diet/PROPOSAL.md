# Diet integration proposal

User asks to move Starting body into Adjust scenario, and add actual editable 7-day meals with visual plates, trustworthy food quantities, macro/fiber/micronutrient totals, day-specific editing, baseline comparison, one-day vs repeated-week scope, meal-to-body visual storytelling, and real model effects. Prior anatomy/sprint/long-term UI must remain simple. Consult Claude before and after implementation.

Plan: native SVG food ingredients on one plate per meal, 4 meals per day (breakfast/lunch/dinner/snack), Monday–Sunday selector. Draw recognizable chicken/beef/fish/eggs/bread/rice/potatoes/produce/nuts/yogurt/cake with quantity-driven scale/count; use cooked/edible food weights. Food +/- and numeric grams; optional replace within category. Compact daily totals, reference vs edited weekly average, collapsed micronutrient overview with computed quantities, explicit missing-data handling and no false green checkmarks. Source per-100g composition from official UK CoFID 2021, preserve food code and exact descriptor. Derive all model calories from the same P/C/F accounting; document carbohydrate convention and fiber treatment. No generic protein/carbohydrate controls in normal scenario UI.

Diet edits are drafts until Run with this diet. Preserve immutable reference and independent edited weekdays. Scope: selected day once, then resume the previously applied week in long-term; or repeat modified week. Reset reference should immediately restore reference inputs while leaving body/activity intact. Export actual food data and selected application scope. Initial/default application is the reference seven-day week.

Model architecture: per-meal macro amounts (not one shared fraction for all macros), food fiber/fat slows a schematic absorption kernel modestly, not a clinical glycemic-index model. Repeating-week absorption includes prior-day carryover, run minute engine across seven days with state carried between days to settle a weekly baseline. Daily food-intake vs absorption difference tracked as gut-energy change, so weekly and day ledgers close. Selected-day override starts from the original week's state, not a synthetic seven-day repeated edited Monday. Long-term samples each actual weekday's macros and TEF in sequence, not just weekly average; a one-day override applies exactly once. Protein adequacy affects the existing illustrative lean adaptation rule. Micronutrients are shown as dietary intake coverage only, not deficiency physiology.

Critical sprint fix: current local glycogen starts at 100% regardless of diet. Seed sprint local glycogen from whole-muscle availability at warm-up start in the diet day's state, and let reduced availability constrain glycolytic power. Keep protected ATP/PCr buffering/fatigue model. Cost replaces normal exercise; avoid two workouts or fake fuel creation. Reference diet calibrates around 2500–2700 kcal and 120–140g protein/day average, adequate plant variety/fiber, two oily-fish meals, calcium foods, normal desserts. Flag vitamin D if food-only intake falls short rather than invent adequacy.

UI: Diet button in header. Spacious modal with weekday navigation, daily totals, 2x2 meal cards with plates and food editors, on-demand nutrient details, sticky action footer with application scope. Meal plate appears briefly in the left scene at meal time, then fades into a small digestion→blood cue while existing nutrient motion continues. No second competing body or wall of text. Starting-body presets become uncommitted fields inside scenario dialog and apply with other settings.
