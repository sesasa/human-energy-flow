# Grouped plots and a guided physiological documentary

User requests: concise left context; grouped time-series on the right replacing most bars in daily, sprint and long modes; playback/timeline/speed/voice under the body; vertical system controls beside the body; authored, event-based narration in all three modes, synchronized to simulation time, pause/resume/speed/seek and plot/anatomy emphasis. Preserve current food/profile/sex/cycle/body behavior and visual language. Consult Claude at beginning and review at end.

Initial implementation proposal for your READ-ONLY critique:

1. Same three-column page. Left contains scene title, three short cues, optional meal plate and expandable explanation. Main central component holds anatomy and a compact transport immediately below. A vertical system rail on its right, below activity vignette, offers Guided/All, Cardiovascular, Metabolism, Muscular, Digestion, Brain, Micronutrients. Selection emphasizes relevant organs and plot cards, does not hide body systems. Right has stable-order plots and compact current readings, no long left live-measure list.
2. Reusable SVG multi-series plot cards with current numerical legends, units, shared cursor and pointer/keyboard scrubbing. Day: glucose/insulin relative signals; liver/muscle glycogen in grams; heart rate bpm; related fat mobilization/recovery/aerobic support normalized teaching indices (explicit labels, not energy fractions). No mixing bpm/percent/grams on one axis. Sprint: ATP+PCr+working glycogen percent of respective reference; fatigue+available power in % but clearly distinct indices; separate heart rate, oxygen index; actual ATP regeneration shares optional compact plot. Plot interval window for sprint, full day otherwise; selected time maps to same master timeline. Long: mass/lean/fat kg grouped with current baseline deltas, body fat % separate, resting HR bpm, selected micronutrient trajectories using existing predictions/reference bands/uncertainty and no invented future lab values. Existing interactive chart can be reused or extended.
3. Author narration events from actual selected meal times, actual schedule, sprint intervals, long-state trends, diet/sex/lab scope. Each event has start/end, concise documentary script, system and plot/series emphasis. Separate from static scene text. Screen shows one short spoken caption. Only speak while playback+voice enabled. No obsolete queue after a seek/mode/input change. Native browser speech synthesis as delivery (existing app already has it), voice choice prefers English natural installed voice; no external TTS credentials/runtime service. Calm rate; no arbitrary forced speed=1 as today.
4. Synchronization: timeline-driven segments. When voice on, narration duration determines safe visual rate within that event. Requested playback speed changes pace (bounded speech rate for intelligibility), but visuals never run into a new event while old speech is playing. Pause/resume preserves current utterance where browser supports it; scrub cancels and next Play starts segment at destination. Silence gap / skipped events have no backlog. Sprint lines must fit real short intervals: split into short phase-specific segments, prioritize first/selected late reps, pace/hold at event boundary only when needed, and clearly indicate narrated pacing. Voice off uses normal speed. Reduced motion retains plot and guide highlighting.
5. Validate chart scales/series against model arrays; narration events conditional on actual diet/time/activity, no universal improvement claims, no single-meal body changes. Test speed changes, pause/resume/seek, end/error fallback using a speech stub plus browser real interface. Browser cannot guarantee all platforms provide an installed speaking voice; disclose concise fallback if none.
