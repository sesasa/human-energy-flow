# Profile, navigation and menstrual iron: design proposal

User request: simplify main navigation to Over Time with secondary “Show Inside a Day”. Only Inside a Day reveals Healthy day / Sprint session plus Back to Over Time. Add sex selector with real physiological effects, neutral female anatomy, optional editable cycle with length/duration/light/typical/heavy bleeding. Cycle affects iron loss and cumulative ferritin, not artificial hormone oscillations of all markers. Show subtle bleeding events on ferritin plot. Keep shared weekly food controls, lab reference provenance, educational uncertainty. User explicitly asks for Claude advice before implementation and final review.

Proposed implementation:
- Default to Over Time; remove visible 1yr/3yr top tabs (timeline already covers these). Preserve remembered long-term position and representative-day menus. Only show daily tabs inside daily view.
- Sex radio in Adjust scenario / Profile. Existing Mifflin–St Jeor already implements +5 male / −161 female. Connect UI and use actual lean mass to scale illustrative gain ceiling, instead of multiplying all physiology by sex. Preserve same food week; show estimated energy budget so energy imbalance is visible.
- Existing presets are authored BMI/bodyfat examples. Add female presets with transparent example labels; avoid implying measured body fat or health targets. Consider using published age/sex/BMI regression solely to contextualize a female example, not overwrite explicit measurements. Sex change can use corresponding preset if current values match a preset; preserve custom body values.
- Neutral female SVG with modest shoulder/pelvic/torso contour changes, same organs and physiology, Front/Back retained. Avoid independent organ displacement or sexualized detail.
- Optional cycle OFF by default, only female. Editable cycle length (21–40 days), bleeding (1–10 days, less than length), light/typical/heavy. Explicit model day 1 = bleeding start (consider start-day field). Not fertility/ovulation prediction, pregnancy, lactation or contraception model.
- Sources so far: National Academies iron DRI (https://www.ncbi.nlm.nih.gov/books/NBK222309/) gives median 27.6mL/cycle, many cohorts medians 20–30mL, 80mL high loss, 3.39mg Fe/g hemoglobin, basal losses .014mg/kg/day. Choose illustrative blood-loss category midpoints 15/30/80mL with clearly documented ranges and Hb assumption 135g/L (~.46mg iron/mL). Could use direct iron-per-cycle categories instead. Losses distributed across bleeding days; no simultaneous average cycle loss (avoid double count). Existing iron pool conservation, recycling and absorption already present.
- Sex/weight-aware basal loss, optional female cyclic additional loss. Keep real stores ledger unfiltered. If needed apply modest observation-buffer smoothing ONLY to displayed ferritin proxy, with day0 exact measured result and explicit authored smoothing assumption. No dramatic monthly jumps or universal recovery curve. Uncertainty includes uptake/loss and bleeding-category variability.
- Ferritin plot subtle bleeding-day bands with simple legend and compact “diet in / daily losses / cycle loss” context. Do not add cycle bands or oscillation to B12/folate/D. User supplied lab limits always override age/sex default. Mayo female ferritin18–50 6–175µg/L, ≥51 11–328; male31–409. State lab interval is not a clinical target or diagnostic threshold.
- Profile must propagate to micronutrient previews, Applied diet, exports, caches, reset and main-timeline watch. Existing bodyfat safety boundaries need review for female (avoid exporting6% female as supported range). Existing legacy male31–50 intake comparisons should become age/sex aware, clearly not a personalized intake prescription.

Give concise, constructive prioritized UX/scientific/architecture recommendations and identify pitfalls, especially menstrual-loss timing, smoothing, presets and cross-panel state.
